# 架构说明

## 分层

```
归档(lossless)      消息原文, 一条不改
   │
索引(lossy)         TF-IDF 词面索引 (字符二元组 + 英文词)
   │
检索                余弦相关度 → 判定 → 修饰权重 → 去重 → 预算内选摘
   │
读出                有序片段 + 折叠指针 (不生成文本)
```

## 检索管线

1. **相关度**:查询向量与每条消息的余弦。长查询按句切分、取"最像那句"的
   最大值,避免整段向量被稀释。
2. **判定**:用**纯相关度**(不是时间加权后的分数)决定是否拒答。
   - `solid`:最高分 ≥ 0.30
   - `weak`:0.15 ~ 0.30
   - 拒答:< 0.15,或查询词全被停用词过滤
3. **修饰权重**:时间衰减 / 新鲜度抑制 / 召回次数增强。
4. **拥挤度自适应**:

   ```
   拥挤度 = 强命中条数(>25% 最高分) / 预算容量(预算 ÷ 平均消息长度)
   抑制系数 = lam × clip(拥挤度, 0.4, 4.0)
   ```

   命中拥挤就狠压(逼它只留代表),命中稀疏就放宽(别浪费预算)。
5. **内容去重**:候选池内贪心聚簇,阈值按池内两两相似度的"均值 + 1 个标准差"
   自适应(长消息余弦被稀释,固定阈值不可用)。每簇留一个代表,其余折叠成指针。
6. **选摘**:代表之间做 MMR,在字符预算内选取,按原顺序输出。

## 状态机会话

```
q <关键词>       新查询
refine <关键词>  重述,时间窗不变
dig [天数]       时间窗往历史滑动 N 天,重新检索
show / reset / finish
```

跨轮硬排除:本次会话已返回的消息不再出现,所以 `dig` 每轮都是新内容;
当返回条数骤减,说明该窗口挖完了,应 `refine` 换词。

## 为什么是抽取式

- 函数层只能做:选、排序、分组、折叠、留指针;
- 把片段"重写成一段话"是生成任务,必须交给下游语言模型;
- 因此归档保持无损,而**读出是有损但可导航的**:骨架 + 指针。

## MCP 接口

服务端 `semantic_memory/mcp_server.py` 用 stdio 传输、JSON-RPC 2.0,零第三方依赖:

| 工具 | 方向 | 说明 |
|---|---|---|
| `recall(query, budget, recent, days_ago)` | 读 | 返回有序片段 + 出处;无相关记忆时诚实拒答 |
| `remember(text, role)` | **写** | 追加消息到档案并重建索引 |
| `stats()` | 读 | 档案条数与时间范围 |

写入路径:`remember` 追加一行 JSON 到 `data/messages.jsonl`,然后重建 TF-IDF 索引
(小档案自动用 `min_df=1`,保证刚写入的内容立刻可被检索)。

## 已知瓶颈

- 词面匹配会在词中间命中("写一首诗" → "写一遍"),导致单条巧合命中;
- 长消息稀释余弦,真正的冗余在段落级,下一步应做段落/句级索引或 span 级打
  分(不改变消息级出处);
- 没有语义 embedding,跨语言/同义改写无法匹配。
